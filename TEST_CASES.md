# Use Cases & Test Cases Matrix

This document tracks the core use cases and lists the complete testing matrix of unit, integration, and BDD acceptance tests verifying the functionality, security rules (Zero Data Leak policy), and performance properties of `mongo-schema-fetch`.

---

## Core Use Cases

### UC-1: Manual Profiling (Developer)
- **Description**: A developer investigates query performance on a local or staging database. They execute `mongo-schema-fetch <uri>` to extract schema structures and performance metrics, inspect the generated `schema-payload.json` to verify no real user data is exposed, and upload the payload to the Web UI via an interactive "Magic Link" to get instant query tuning recommendations.
- **Key Verification Points**: Interactive console prompt for manual collection selection, correct file generation, zero actual data leak, and the interactive prompt for uploading via magic link opening the browser.

### UC-2: CI/CD Pipeline Integration (Automation)
- **Description**: The utility runs silently in a CI/CD pipeline (e.g. GitHub Actions) against a test database. The extracted schema payload along with a query definition file is automatically submitted to the Web Optimizer API using `--auto-analyze`. If the API returns a degradation warning (e.g. Full Collection Scan detected), the pipeline exits with code `1`, blocking deployment.
- **Key Verification Points**: Quiet mode silencing all console prompts, query validation parameters, Mock API auto-analysis invocation, and correct exit codes mapping to pipeline fail/pass statuses.

### UC-3: Production Secondary Scan (DBA/Analyst)
- **Description**: An analyst or DBA runs the schema extraction on a production cluster. To avoid adding lock contention or CPU overhead on the primary writing node, they use the `--read-preference secondary` flag to query a secondary node.
- **Key Verification Points**: Database connection receives and respects read preference configurations.

### UC-4: Resilient Database Privilege Execution (Permissions Tolerance)
- **Description**: The utility runs successfully in environments where the user is granted restrictive read-only permissions on select databases and collections, without throwing fatal connection or query execution errors.
- **Key Verification Points**: Admin command failures (like buildInfo/hostInfo) are handled gracefully; collection stats queries fall back to count estimations; index queries fall back to empty structures on privilege failure.

### UC-5: Memory-Safe Smart Sampling & OOM Prevention
- **Description**: When analyzing large collections containing very large documents, loading all records into memory at once would trigger Node.js Out-Of-Memory (OOM) failures or over-burden the database CPU. The utility automatically controls sampling rates and reads database cursors via streams.
- **Key Verification Points**: Dynamic sampling size (50 to 1000) based on `avgObjSize`; streaming records via Node.js Readable Stream instead of `toArray()`; `maxTimeMS` execution limits.

### UC-6: Storage-Model Awareness (Views, Time-Series, Capped, Clustered collections)
- **Description**: Downstream query optimization engines behave differently depending on the collection storage models. For example, index recommendations must be disabled for views, and bucket-friendly, compressed indexes must be prioritised for timeseries collections. The utility extracts collection structure metadata to support storage-model awareness.
- **Key Verification Points**: Extracting collection `type` (e.g. `"timeseries"`, `"view"`, `"collection"`), storage configuration parameters (`options`), and enforced validation rules (`validator` `$jsonSchema` constraints).

### UC-7: Extended Database Engine Telemetry (Diagnostics)
- **Description**: Operators and automated optimization systems require performance indicators to diagnose query stalls, read/write ticket exhaustion, memory dirty limits, and latency spikes. The utility extracts concurrency tickets, eviction metrics, cache dirty rates, plan cache details, and read/write latency distributions.
- **Key Verification Points**: WiredTiger ticket usage (`concurrentTransactions`), cache dirty ratio (`cacheDirtyRatio`), active application page eviction (`pagesEvictedByApp`), and conditional execution plan shapes (`planCache`) and latency histograms (`latencyStats`) when `--additional` is active.
