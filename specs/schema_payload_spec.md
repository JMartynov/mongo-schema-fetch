# MongoDB Schema Payload Format Specification

This specification defines the JSON schema payload format generated by `mongo-schema-fetch`. The utility extracts structural metadata, index statistics, collection metrics, and database contexts without violating security rules (Zero Data Leak policy).

---

## 1. Document Overview

The output payload is a single, self-contained JSON document that matches a strict validation schema verified by `ajv`. The structure consists of two main root properties:

```json
{
  "serverContext": { ... },
  "collections": [ ... ]
}
```

- **[serverContext](#2-servercontext)**: Details regarding the target MongoDB engine, version, and host context.
- **[collections](#3-collections-array)**: An array containing the schema definitions, collection statistics, and index usage details for all analyzed collections.

---

## 2. serverContext

Provides the environment context of the profiled database. This is critical for downstream analysis because optimizer engines rely on version-specific query planner rules (e.g. changes between MongoDB 6.0 and 8.0).

### Schema Properties

- `buildInfo` (Object, **Required**): The raw output of MongoDB's `buildInfo` admin command.
  - `version` (String, **Required**): The semantic version of the database (e.g. `"7.0.5"`).
  - `gitVersion` (String): The git commit hash of the build.
  - `versionArray` (Array of Numbers): The version split into digits (e.g. `[7, 0, 5, 0]`).
  - `bits` (Number): Architecture bits (e.g., `64`).
  - `ok` (Number): MongoDB status code (`1`).
- `hostInfo` (Object, **Optional**): The sanitized output of the `hostInfo` command. Contains information about the CPU, OS, and memory sizes of the server host. Empty if cluster access privileges are restricted. To prevent network names or hostname leaking (Zero Data Leak Policy), the `hostname` property under `system` and the entire `extra` object are strictly removed.
- `cpuArch` (String, **Optional**): The CPU architecture extracted from `hostInfo` (e.g. `"x86_64"` or `"aarch64"`).
- `memSizeMB` (Number, **Optional**): The total host memory size in Megabytes extracted from `hostInfo`.
- `numProcessors` (Number, **Optional**): The number of physical or logical CPU cores/processors extracted from `hostInfo`.
- `wiredTigerCacheBytes` (Number, **Optional**): The engine-level configured maximum memory cache in bytes extracted from `serverStatus.wiredTiger.cache`.
- `concurrentTransactions` (Object, **Optional**): Contains `read` and `write` concurrency ticket profiles (out and available slots).
- `cacheDirtyRatio` (Number, **Optional**): Percentage ratio of tracked dirty bytes in cache to the total cache capacity.
- `pagesEvictedByApp` (Number, **Optional**): Cumulative pages evicted by application client threads under high storage pressure.

### Example
```json
"serverContext": {
  "buildInfo": {
    "version": "7.0.8",
    "gitVersion": "e44d320...",
    "versionArray": [7, 0, 8, 0],
    "bits": 64,
    "ok": 1
  },
  "hostInfo": {
    "system": {
      "cpuAddrSize": 64,
      "memSizeMB": 16384,
      "numProcessors": 8,
      "cpuArch": "x86_64"
    },
    "os": {
      "type": "Darwin",
      "name": "Mac OS X",
      "version": "14.4"
    }
  },
  "cpuArch": "x86_64",
  "memSizeMB": 16384,
  "numProcessors": 8,
  "wiredTigerCacheBytes": 8589934592
}
```

## 3. collections Array

An array containing descriptors for each profiled collection. Each collection entry contains three major components:

```json
{
  "stats": { ... },
  "indexes": { ... },
  "schema": { ... }
}
```

### 3.1. stats (Collection Statistics)
Contains database storage and size statistics for the collection. If the `collStats` command fails due to database access privilege restrictions, the utility falls back to estimation.

- `name` (String, **Required**): The name of the collection.
- `count` (Number, **Required**): Precise or estimated document count.
- `estimatedDocumentCount` (Number, **Required**): Fast metadata document count.
- `avgObjSize` (Number, **Required**): Average document size in bytes. Used by the utility to determine dynamic sampling limits.
- `totalIndexSize` (Number, **Required**): Cumulative size of all collection indexes in bytes.
- `type` (String, **Optional**): The collection storage type (e.g. `"collection"`, `"view"`, `"timeseries"`).
- `options` (Object, **Optional**): Metadata options from the collection configuration (e.g., capped constraints, timeseries specifications, clustered index details).
- `validator` (Object, **Optional**): Database-enforced schema validations (like `$jsonSchema` validators).
- `planCache` (Array, **Optional**): Cached execution plans retrieved from the engine (only populated under `--additional`).
- `latencyStats` (Object, **Optional**): Read/write latency histograms detailing operational response times (only populated under `--additional`).

#### Example
```json
"stats": {
  "name": "users",
  "count": 1500,
  "estimatedDocumentCount": 1500,
  "avgObjSize": 182,
  "totalIndexSize": 81920
}
```

### 3.2. indexes (Index Definitions and Usage)
Contains index structures and access rates.

- `name` (String, **Required**): The name of the collection.
- `indexes` (Array, **Required**): The raw output of MongoDB's `db.collection.indexes()` command. Each index contains its version (`v`), the key definitions (`key`), and options (like `unique` or `sparse`).
- `indexStats` (Array, **Required**): The usage statistics retrieved via MongoDB's `$indexStats` aggregation stage. Contains how many times an index was used (`accesses.ops`) and when tracking started.

#### Example
```json
"indexes": {
  "name": "users",
  "indexes": [
    { "v": 2, "key": { "_id": 1 }, "name": "_id_" },
    { "v": 2, "key": { "email": 1 }, "name": "email_1", "unique": true }
  ],
  "indexStats": [
    {
      "name": "email_1",
      "key": { "email": 1 },
      "host": "localhost:27017",
      "accesses": { "ops": 1420, "since": "2026-01-01T00:00:00Z" }
    }
  ]
}
```

## 4. schema (Probabilistic Inferred Schema)

The `schema` property contains the probabilistic structure inferred by `mongodb-schema` and scrubbed by the utility's `cleanSchema` module.

### 4.1. Root Schema Properties
- `count` (Number, **Required**): The total number of documents sampled for this inference.
- `fields` (Array of Field Descriptors, **Required**): Top-level field definitions.

### 4.2. Field Descriptor Structure
Describes a field name and its observed type parameters.

- `name` (String, **Required**): The field name key.
- `path` (Array of Strings, **Required**): The full hierarchical path of the field (e.g. `["address", "city"]`).
- `count` (Number, **Required**): The number of documents in the sample that contain this field.
- `type` (String, **Required**): The dominant type of the field. Set to `"Mixed"` if multiple type definitions are present.
- `probability` (Number, **Required**): The probability of the field occurring in a document (range: `0.0` to `1.0`).
- `hasDuplicates` (Boolean, **Required**): Whether duplicate values were detected for this field in the sample.
- `types` (Array of Type Descriptors, **Required**): The breakdown of all observed types for this field.

### 4.3. Type Descriptor Structure
Details a specific type profile for a field. A single field can have multiple type descriptors if the field is polymorphic (contains mixed types).

- `name` (String, **Required**): The type name. Common values are:
  - `"String"`, `"Number"`, `"ObjectID"`, `"Date"`, `"Boolean"`, `"Null"`, `"Document"`, `"Array"`.
- `bsonType` (String, **Required**): The BSON-compliant type string (matches `name` or BSON representations).
- `path` (Array of Strings, **Required**): Path of the field.
- `count` (Number, **Required**): Sample occurrence count for this specific type.
- `probability` (Number, **Required**): Probability of this type occurring.
- `unique` (Number): The unique value count for this type observed in the sample.
- `hasDuplicates` (Boolean, **Required**): Whether duplicate values were found for this type.
- `enumValues` (Array, **Conditional**): Low-cardinality enumeration values (see [Zero Data Leak Policy](#5-zero-data-leak-policy-and-invariants)).
- `fields` (Array of Field Descriptors, **Conditional**): Present only when `name === "Document"`. Recursively describes subdocument fields.
- `types` (Array of Type Descriptors, **Conditional**): Present only when `name === "Array"`. Recursively describes the types of items inside the array.

## 5. Zero Data Leak Policy and Invariants

To guarantee that no sensitive user data (like passwords, personally identifiable information, or raw business data) leaks into the exported schema payload, the utility enforces the following strict invariants during the `cleanSchema` phase:

1. **Unconditional Values Wipe**:
   - The raw `values` array produced by the `mongodb-schema` library is **strictly deleted** for all field types. No actual values (including `ObjectId` or `Date` values) ever remain in the final payload.
2. **Safe Low-Cardinality Enums**:
   - Enumerated values are only preserved for `"String"` and `"Number"` types.
   - The number of unique values in the sample must be less than the `--enum-threshold` (default is 20).
   - For string enums, any string value exceeding **100 characters** is discarded to prevent storing long sentences or text blocks.
3. **Array Type Cleaning**:
   - Array types contain a nested `types` array (detailing the array elements' type profiles). The clean phase recursively traverses these nested type descriptors, stripping their raw `values` and preserving only safe enums.

## 6. Comprehensive Format Example

Below is an annotated example of a generated `schema-payload.json` file highlighting nested objects, arrays, and enum sanitization:

```json
{
  "serverContext": {
    "buildInfo": {
      "version": "7.0.8",
      "gitVersion": "e44d320...",
      "versionArray": [7, 0, 8, 0],
      "bits": 64,
      "ok": 1
    }
  },
  "collections": [
    {
      "stats": {
        "name": "users",
        "count": 12000,
        "estimatedDocumentCount": 12000,
        "avgObjSize": 250,
        "totalIndexSize": 81920
      },
      "indexes": {
        "name": "users",
        "indexes": [
          { "v": 2, "key": { "_id": 1 }, "name": "_id_" }
        ],
        "indexStats": []
      },
      "schema": {
        "count": 1000,
        "fields": [
          {
            "name": "_id",
            "path": ["_id"],
            "count": 1000,
            "type": "ObjectId",
            "probability": 1.0,
            "hasDuplicates": false,
            "types": [
              {
                "name": "ObjectId",
                "bsonType": "ObjectId",
                "path": ["_id"],
                "count": 1000,
                "probability": 1.0,
                "hasDuplicates": false
                // Note: "values" array has been stripped
              }
            ]
          },
          {
            "name": "role",
            "path": ["role"],
            "count": 1000,
            "type": "String",
            "probability": 1.0,
            "hasDuplicates": true,
            "types": [
              {
                "name": "String",
                "bsonType": "String",
                "path": ["role"],
                "count": 1000,
                "probability": 1.0,
                "unique": 2,
                "hasDuplicates": true,
                "enumValues": ["admin", "user"] // Safe low-cardinality enum
              }
            ]
          },
          {
            "name": "address",
            "path": ["address"],
            "count": 950,
            "type": "Document",
            "probability": 0.95,
            "hasDuplicates": true,
            "types": [
              {
                "name": "Document",
                "bsonType": "Object",
                "path": ["address"],
                "count": 950,
                "probability": 0.95,
                "hasDuplicates": true,
                "fields": [
                  {
                    "name": "city",
                    "path": ["address", "city"],
                    "count": 950,
                    "type": "String",
                    "probability": 1.0,
                    "hasDuplicates": true,
                    "types": [
                      {
                        "name": "String",
                        "bsonType": "String",
                        "path": ["address", "city"],
                        "count": 950,
                        "probability": 1.0,
                        "unique": 3,
                        "hasDuplicates": true,
                        "enumValues": ["London", "Paris", "New York"]
                      }
                    ]
                  }
                ]
              }
            ]
          },
          {
            "name": "tags",
            "path": ["tags"],
            "count": 800,
            "type": "Array",
            "probability": 0.8,
            "hasDuplicates": true,
            "types": [
              {
                "name": "Array",
                "bsonType": "Array",
                "path": ["tags"],
                "count": 800,
                "probability": 0.8,
                "hasDuplicates": true,
                "types": [
                  {
                    "name": "String",
                    "bsonType": "String",
                    "path": ["tags"],
                    "count": 1600, // Multi-element counts
                    "probability": 1.0,
                    "unique": 2,
                    "hasDuplicates": true,
                    "enumValues": ["news", "tech"] // Inner elements values stripped, enums preserved
                  }
                ]
              }
            ]
          }
        ]
      }
    }
  ]
}
```
